# Road map спринтов (средняя версия)

## Для чего этот roadmap

План помогает дойти от проектной документации до рабочей и проверенной прошивки ESP32-S3 на **Arduino IDE**.

## Логика движения

```mermaid
flowchart LR
  Foundation[1-3: База] --> Runtime[4-5: Локальный цикл]
  Runtime --> Network[6-7: Локальный и удаленный доступ]
  Network --> Reliability[8-9: Надежность и безопасность]
  Reliability --> Beta[10: Полевое бета]
```

## По спринтам

### Спринт 1 — Сборка и инфраструктура
- Что делаем: структура проекта, версия core, сборка и загрузка через Arduino IDE, CI, README.
- Результат: любой участник собирает прошивку с нуля в Arduino IDE, CI стабильно зеленый.

### Спринт 2 — Датчики
- Что делаем: SCD41, MLX90614, вода, stale-age, retry и fault-модель.
- Результат: показания стабильны, отказ канала обрабатывается предсказуемо.

### Спринт 3 — Приводы
- Что делаем: fan/hum/light, safe OFF, emergency-safe поведение.
- Результат: нет опасных автозапусков нагрузок при boot/reboot.

### Спринт 4 — FSM + рецепт
- Что делаем: жизненный цикл по `docs/architecture/state-machine.md`, snapshot рецепта в `ACTIVE_RUN`.
- Результат: `select -> start -> pause -> resume` работает без сети.

### Спринт 5 — Контур климата
- Что делаем: один замкнутый контур + арбитраж и hard limits.
- Результат: стендовая стабилизация RH/CO2 и корректный trace.

### Спринт 6 — AP HTTP
- Что делаем: SoftAP + минимальные endpoint'ы из `docs/api/ap-contract.md`.
- Результат: локально видно статус/сенсоры и можно работать с рецептами.

### Спринт 7 — MQTT
- Что делаем: команды/ack/telemetry, dedup по `msg_id`, off-line очередь.
- Результат: удаленные команды не дублируются при ретраях.

### Спринт 8 — Логи и время
- Что делаем: ring buffer, SD-flush, NTP и TZ policy.
- Результат: сутки работы без потери критичных логов.

### Спринт 9 — Service mode и hardening
- Что делаем: безопасные service-команды, stage guards, security меры (TLS/anti-replay).
- Результат: сервис не ломает safety-инварианты.

### Спринт 10 — Полевое бета
- Что делаем: soak-тест, сбор инцидентов, стабилизация release-кандидата.
- Результат: понятный список ограничений v1 и готовность к пилоту.

## Чекпоинты по фазам

- **Фаза A (1-3):** железо читается и управляется безопасно.
- **Фаза B (4-5):** локальная автоматика работает устойчиво.
- **Фаза C (6-8):** подключение + телеметрия + время надежны.
- **Фаза D (9-10):** эксплуатационная безопасность и полевой прогон закрыты.

## Главные риски

- I2C и питание могут задержать спринты 2-3.
- Сетевые фичи нельзя ускорять раньше стабилизации локального цикла.
- Если YAML тяжёл для устройства, валидацию держать в CI, а на устройство подавать подготовленный формат.

## Оценка сроков

- Один разработчик: примерно 5-6 месяцев.
- Два разработчика: быстрее за счет параллельной работы (железо/сеть).
